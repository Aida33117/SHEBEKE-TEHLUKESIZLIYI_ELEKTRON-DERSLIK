10.1. MAS (IDS)/MQS (IPS) sistemlərinə giriş

IDS (Intrusion Detection System) – MAS (Müdaxilələrin Aşkarlanması Sistemi) şəbəkə və ya host fəaliyyətini müşahidə edir, şübhəli nümunələri müəyyənləşdirir və xəbərdarlıq yaradır. IPS (Intrusion Prevention System) – MQS (Müdaxilələrin Qarşısının Alınması Sistemi) isə trafiki yoxlamaqla yanaşı, siyasətə uyğun olaraq paketi buraxa, bloklaya, ata və ya bağlantını sıfırlaya bilər.

Detection

Hadisəni aşkarlamaq və analitikə bildirmək. IDS çox vaxt müşahidə rejimində işləyir.

Prevention

Uyğun qayda olduqda təhlükəli hesab edilən trafikin qarşısını almaq. IPS adətən inline yerləşdirilir.

Alert

Qayda və ya modelin yaratdığı xəbərdarlıq. Alert hər zaman təsdiqlənmiş insident demək deyil.

Incident

Təhlükəsizlik siyasətinə və aktivlərə təsiri olan, araşdırılmalı hadisə.

10.2. MAS (IDS) işləmə mexanizmi və növləri

IDS sensoru trafik və ya host hadisələrini toplayır. Detection Engine bu məlumatları imza, anomaliya və davranış qaydaları ilə müqayisə edir. Uyğunluq aşkarlandıqda Alert Generation mərhələsi xəbərdarlıq yaradır, Event Logging isə hadisəni sonrakı araşdırma üçün saxlayır.

Aşkarlama metodları

Signature-Based

Əvvəlcədən məlum imza və qaydalarla uyğunluq axtarır. Məlum nümunələri yaxşı aşkarlaya bilər, yeni və dəyişmiş nümunələri qaçıra bilər.

Anomaly-Based

Normal davranış profilindən kənara çıxmanı tapır. Yeni anomaliyaları görə bilər, lakin normal dəyişikliklər false positive yarada bilər.

Behavior-Based

Fəaliyyət ardıcıllığı və davranış nümunələrini qiymətləndirir. Tək hadisədən çox kontekstə baxır.

Rule-Based

Administratorun yazdığı şərtlər və siyasət qaydaları əsasında aşkarlayır.

IDS Detection Simulator

Metod və sintetik trafik seçin.

False Positive nümunəsi: universitetin imtahan günü artan qanuni girişləri anomaliya kimi işarələnə bilər. False Negative nümunəsi: yeni hücum məlum imza bazasında olmadığı üçün imza əsaslı sistem tərəfindən qaçırıla bilər.

10.3. MQS (IPS) işləmə mexanizmi və növləri

IPS adətən şəbəkə yolunda (inline) yerləşir. Paketlər sistemdən keçərkən qaydalarla yoxlanılır. Siyasətə görə ALLOW, BLOCK/DROP, RESET və ALERT qərarları yarana bilər. Yanlış bloklama (false blocking) biznes xidmətini dayandıra biləcəyindən qaydalar əvvəlcə sınaqdan keçirilməlidir.

10.6. Təhlükəsizlik Əməliyyatları Mərkəzi (SOC)

SOC (Security Operations Center) təşkilatın təhlükəsizlik hadisələrini davamlı izləyən, təhlil edən, araşdıran və cavab tədbirlərini koordinasiya edən komanda, proses və texnologiyalar toplusudur.

Tier 1 – Triage

Xəbərdarlığı qəbul edir, ilkin yoxlama aparır, false positive ehtimalını qiymətləndirir və eskalasiya edir.

Tier 2 – Investigation

Hadisənin əhatəsini, səbəbini və təsirini araşdırır; containment tövsiyə edir.

Tier 3 – Threat Hunting / Engineering

Mürəkkəb təhdidləri araşdırır, aşkarlama məntiqini təkmilləşdirir və qabaqlayıcı axtarış aparır.

SOC analitiki tapşırığı

Wazuh yüksək prioritetli giriş xəbərdarlığı yaradıb. Snort eyni mənbədən şübhəli trafik qeydə alıb. Növbəti addımınızı seçin.

İnsidentlərə cavab (Incident Response) laboratoriyası

NIST yanaşmasının tədris üçün sadələşdirilmiş mərhələləri: Preparation, Detection and Analysis, Containment, Eradication, Recovery, Post-Incident Activity. Müasir NIST SP 800-61 Rev. 3 insident cavabını CSF 2.0 risk idarəetməsi ilə inteqrasiya edir; bu mərhələlər tədris axını kimi istifadə olunur.

1. Preparation – Hazırlıq

Aktiv inventarı, kontaktlar, playbook, ehtiyat nüsxə, loglama və rol bölgüsü.

2. Detection and Analysis – Aşkarlama və təhlil

Alert-in doğrulanması, log/paket korrelyasiyası, əhatə və təsirin qiymətləndirilməsi.

3. Containment – Təcridetmə

Təsirlənmiş hostu məhdudlaşdırmaq, hesabı müvəqqəti kilidləmək, zəruri sübutları qorumaq.

4. Eradication – Aradan qaldırma

Səbəbi aradan qaldırmaq, zəifliyi bağlamaq, zərərli komponenti təmizləmək.

5. Recovery – Bərpa

Təmiz ehtiyat nüsxədən bərpa, nəzarətli işə qaytarma və gücləndirilmiş monitorinq.

6. Post-Incident Activity – Hadisədən sonrakı təhlil

Dərslər, hesabat, qaydaların təkmilləşdirilməsi və göstəricilərin yenilənməsi.

Ssenari və tədbir seçin.

10.7. Yoxlama sualları

Bu bölmə 20 real iş mühitinə yaxın situasiya əsasında qurulub. Hər ssenaridə tələbə SOC analitiki kimi hadisəni təhlil etməli, sübutları korrelyasiya etməli, risk və biznes təsirini qiymətləndirməli, uyğun cavab tədbirini seçməlidir. Cavabı yoxladıqda düzgün seçim və izah göstərilir.

Qiymətləndirmə meyarı

Hər düzgün cavab 1 baldır. Maksimum nəticə 20 baldır. 18–20: əla; 15–17: yaxşı; 12–14: kafi; 0–11: mövzuların təkrar öyrənilməsi tövsiyə olunur.

10.8. Praktiki tapşırıq

Tapşırıqları asandan mürəkkəbə doğru yerinə yetirin. Hər tapşırıq üçün məqsəd, nəzəri hazırlıq, proqram, ilkin məlumat, topologiya, addımlar, gözlənilən nəticə, yoxlama sualları, qiymətləndirmə və hesabat tələb olunur.

  1. IDS və IPS sistemlərinin virtual arxitekturasını qurun.
  2. İmza əsaslı aşkarlama qaydalarını sintetik trafikdə tətbiq edin.
  3. Anomaliya əsaslı aşkarlama mexanizmini simulyasiya edin.
  4. Snort vasitəsilə sintetik hadisələri aşkarlayın.
  5. Suricata vasitəsilə trafik və EVE JSON hadisələrini təhlil edin.
  6. Wazuh SIEM-də sintetik logları araşdırın.
  7. Wireshark ilə şübhəli paketləri araşdırın.
  8. SOC analitiki kimi insidentə cavab verin.

Hesabat forması

1. Məqsəd; 2. Nəzəri əsas; 3. İstifadə edilən proqramlar; 4. Topologiya; 5. İlkin sintetik məlumatlar; 6. Qaydalar və konfiqurasiya; 7. Alert və log nəticələri; 8. Korrelyasiya; 9. Cavab tədbirləri; 10. Nəticə və özünüqiymətləndirmə.

  3. IPS müdafiə qərarlarını müqayisə edin.
  4. İmza və anomaliya aşkarlamasını tətbiq edin.
  5. Snort qaydaları və alert-ləri təhlil edin.
  6. Suricata hadisələri və EVE JSON çıxışını araşdırın.
  7. Wireshark ilə paketləri təhlil edin.
  8. Wazuh SIEM loglarını toplayıb korrelyasiya edin.
  9. SOC panelində hadisəni araşdırın.
  10. Incident Response mərhələlərini seçin və yekun hesabat hazırlayın.
