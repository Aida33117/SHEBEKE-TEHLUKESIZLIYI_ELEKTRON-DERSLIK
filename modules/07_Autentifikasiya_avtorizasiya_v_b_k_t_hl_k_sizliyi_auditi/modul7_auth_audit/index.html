Modul istifadəçinin kimliyinin yoxlanılmasını, ona hansı əməliyyatların icazəli olmasını və sistemdəki fəaliyyətlərin qeydə alınmasını öyrədir. Əsas sual: kim daxil olur, nə edə bilər və nə edib?

Terminoloji qeyd: AAA-da Accounting fəaliyyətlərin uçotu və qeydiyyatıdır. Təhlükəsizlik auditi isə qeydlərin və nəzarət mexanizmlərinin daha geniş təhlilidir.

7.1. Təhlükəsizlik konsepsiyası – AAA (Authentication, Authorization, Accounting)

AAA şəbəkə girişinin idarə edilməsini üç əlaqəli mərhələyə bölür. Autentifikasiya kimliyi təsdiqləyir, avtorizasiya icazələri yoxlayır, Accounting isə fəaliyyəti qeydə alır.

Authentication

İstifadəçi özünü login ilə təqdim edir; sistem parol, token, sertifikat və ya biometrik faktorla yoxlayır.

Nəticə: kimlik təsdiq və ya rədd edilir.

Authorization

İstifadəçinin hansı resursu oxuya, dəyişə, silə və ya idarə edə biləcəyi müəyyən olunur.

Nəticə: icazə və ya imtina.

Accounting

Giriş vaxtı, resurs, əməliyyat və sessiyanın müddəti qeydə alınır.

Nəticə: audit izi.

AAA arxitekturasının iştirakçıları

Client/Supplicant: giriş istəyən istifadəçi və ya cihaz. Authenticator: AP, switch, VPN gateway və ya şəbəkə qurğusu. AAA server: siyasəti yoxlayır. Resource: fayl serveri, tətbiq və ya verilənlər bazası.

Mənbə dərsliyində AAA autentifikasiya, avtorizasiya və qeydiyyatın birlikdə təhlükəsiz interfeys yaratması kimi izah edilir.

7.2. Autentifikasiya (doğrulama)

Autentifikasiya istifadəçinin və ya cihazın təqdim etdiyi kimlik iddiasının yoxlanmasıdır. İstifadəçi adı identifikator, parol isə onu təsdiqləmək üçün sübut ola bilər.

Autentifikasiya faktorları

Bildiyin faktor

Parol, PIN. Oğurlana, təxmin edilə və fişinq yolu ilə ələ keçirilə bilər.

Sahib olduğun faktor

Telefon, token, smart kart, təhlükəsizlik açarı.

Olduğun faktor

Barmaq izi, üz və səs kimi biometrik xüsusiyyət.

MFA iki və ya daha çox fərqli faktorun birləşməsidir. Parol + təhlükəsizlik açarı iki fərqli faktordur; iki parol isə deyil.

OTP, TOTP, Push və FIDO2

  • OTP: birdəfəlik parol, məhdud müddət və ya bir dəfə istifadə üçün.
  • TOTP: vaxt pəncərəsi və ortaq sirr əsasında yaradılan birdəfəlik kod.
  • Push: telefona göndərilən giriş təsdiq sorğusu; istifadəçi konteksti yoxlamalıdır.
  • FIDO2/WebAuthn: fişinqə davamlı açar əsaslı autentifikasiya.

RADIUS iş axını

RADIUS şəbəkəyə giriş, VPN və 802.1X ssenarilərində geniş istifadə olunur. Şəbəkə qurğusu sorğunu serverə ötürür, server siyasəti yoxlayaraq qəbul, rədd və ya əlavə yoxlama tələb edən cavab verir.

TACACS+

TACACS+ əsasən şəbəkə avadanlığının administrator girişinin idarə edilməsində istifadə edilir. Autentifikasiya, avtorizasiya və uçotun ayrılması idarəetməni detallı etməyə kömək edir. RADIUS və TACACS+ eyni protokol deyil və istifadə ssenariləri fərqlənir.

MeyarRADIUSTACACS+

DaşınmaUDPTCP

Kerberos və LDAP

Kerberos parolu hər xidmətə yenidən göndərmədən bilet (ticket) əsasında autentifikasiya yaradır. KDC daxilində Authentication Server (AS) və Ticket Granting Server (TGS) funksiyaları olur. Client əvvəl TGT, sonra konkret xidmət üçün Service Ticket alır.

LDAP kataloq xidmətlərinə sorğu vermək və obyektləri idarə etmək protokoludur. İstifadəçi, qrup, kompüter və təşkilati bölmələr kataloqda iyerarxik saxlanıla bilər. Active Directory LDAP sorğularını dəstəkləyir, eyni zamanda Kerberos, DNS və digər xidmətlərlə inteqrasiya olunur.

7.3. Parol təhlükəsizliyi

Parol təhlükəsizliyinin məqsədi parolun təxmin edilməsini, sızmış parolların təkrar istifadəsini və parol bazası oğurlandıqda açıq mətnlərin əldə edilməsini çətinləşdirməkdir. Uzun, unikal parol ifadəsi və parol meneceri faydalıdır.

Hash və Salt

Server parolu açıq mətn kimi saxlamamalıdır. Parol daxil ediləndə uyğun parol-hash funksiyası ilə yoxlanılır. Salt hər hesab üçün unikal təsadüfi dəyərdir. Parol saxlamaq üçün Argon2, bcrypt və scrypt kimi məqsədli funksiyalar istifadə olunur. SHA-256 ümumi hash funksiyasıdır, təkbaşına parol saxlamaq üçün uyğun seçim deyil.

7.4. Avtorizasiya – girişə nəzarət modelləri

Autentifikasiya uğurlu olduqdan sonra avtorizasiya istifadəçinin konkret resurs üzərində hansı əməliyyatı yerinə yetirə biləcəyini müəyyən edir.

DAC

Resurs sahibi digər istifadəçilərə giriş hüququ verə və ya geri ala bilər. Fayl paylaşımı nümunədir.

MAC

Mərkəzi siyasət və təhlükəsizlik etiketləri əsasında giriş verilir; istifadəçi etiketi özbaşına dəyişmir.

RBAC

İcazələr rollara bağlanır; istifadəçi rola daxil edilir. Müəllim və tələbə rolları nümunədir.

ABAC

Qərar istifadəçi, resurs, əməliyyat və mühit atributlarına əsaslanır.

7.5. Şəbəkə təhlükəsizliyi auditi

Audit sistemin konfiqurasiyalarını, giriş hüquqlarını, hadisə qeydlərini və təhlükəsizlik siyasətlərinə uyğunluğu sistemli şəkildə yoxlayır.

1. Əhatə dairəsi: yoxlanacaq server, şəbəkə seqmenti və hesablar müəyyən edilir.
2. İnventar: istifadəçilər, qruplar, cihazlar və xidmət hesabları siyahıya alınır.
3. Hüquq və konfiqurasiya: parol siyasəti, MFA, administrator hüquqları və qruplar yoxlanılır.
4. Log təhlili: uğursuz giriş, qeyri-adi vaxt, yeni hesab və imtiyaz artımı araşdırılır.
5. Risk qiymətləndirilməsi: ehtimal və təsir nəzərə alınır.
6. Hesabat: tapıntı, sübut, risk, məsul şəxs və son tarix yazılır.

Ssenari: Universitetin mərkəzləşdirilmiş giriş infrastrukturu

Rektorluq, dekanlıq, müəllimlər, tələbələr və İT administratorları üçün vahid giriş infrastrukturu qurulur. Hər qrup yalnız öz səlahiyyətinə uyğun resurslardan istifadə etməlidir.

İcra mərhələləri

  1. VirtualBox-da Linux və Windows Server VM yaradın; host-only və ya daxili şəbəkə seçin.
  2. Serverlər üçün statik IP, müştərilər üçün uyğun ünvanlama və DNS planlaşdırın.
  3. Windows Server-də AD DS quraşdırın, domen, OU, istifadəçi və qruplar yaradın.
  4. Linux VM-də FreeRADIUS quraşdırın, test istifadəçiləri və client konfiqurasiyası hazırlayın.
  5. RADIUS sorğularını test edin; Access-Accept və Access-Reject nəticələrini şərh edin.
  6. RBAC cədvəli qurun və minimum hüquqları təyin edin.
  7. Kerberos/LDAP axınını laboratoriya trafikində müşahidə edin.
  8. Giriş hadisələrini toplayın, log təhlili və audit hesabatı hazırlayın.
Texniki qeyd: FreeRADIUS və Active Directory inteqrasiyası DNS, vaxt sinxronizasiyası, sertifikat və firewall parametrləri tələb edə bilər. Bu səhifədəki sxemlər real server deyil, öyrədici modellərdir.

7.8. Praktiki tapşırıq

1. Ofis şəbəkəsində MFA

Parol faktoruna TOTP və ya təhlükəsizlik açarı əlavə edin. Uğurlu və uğursuz giriş ssenarilərini müqayisə edin; bərpa kodlarının qorunmasını izah edin.

2. Veb tətbiqinin təhlükəsizlik auditi

Yalnız öz test tətbiqinizdə və ya tədris laboratoriyasında SQL injection, XSS və CSRF risklərinin mahiyyətini araşdırın. İcazəsiz sistemləri skan etməyin.

3. Active Directory-də istifadəçi və qruplar

Test domenində Staff, Students və IT-Admins qrupları yaradın; OU strukturunu hazırlayın və nümunə Group Policy tətbiq edin.

4. RADIUS autentifikasiyası

FreeRADIUS test mühitində iki test hesabı yaradın. Birinin girişini qəbul, digərinin girişini rədd etdirin və log nəticələrini izah edin.

5. RBAC və MAC siyasəti

Universitet resursları üçün rol matrisi yaradın, sonra məxfilik etiketləri ilə müqayisə edin. Həddindən artıq hüquqları müəyyən edib düzəldin.

6. Audit jurnalları

Uğursuz girişlərin sayını, mənbə IP-lərini, vaxtları və imtiyaz dəyişikliklərini təhlil edin. Hadisə, risk və tədbir sütunları olan hesabat hazırlayın.
