Şəbəkə təhlükəsizliyi · 4-cü modul

Şəbəkənin idarə edilməsi

Mövzuları gündəlik nümunələr, addım-addım izahlar, sxemlər, müqayisə cədvəlləri və interaktiv yoxlamalarla öyrənin. SNMP, Syslog, Zabbix və Wireshark vasitəsilə şəbəkənin monitorinqini tətbiq edin.

Ssenari: 3 korpus · Hər korpusda 3 mərtəbə · Universitet şəbəkəsi

Bu modulda nə öyrənəcəksiniz?

Yeni genişləndirilmiş izah: Hər mövzu əvvəl sadə analogiya ilə izah edilir, sonra texniki termin, real universitet nümunəsi, diaqram və özünü yoxlama tapşırığı verilir.

Şəbəkənin idarəetmə prinsipləri və parametrləri, mərkəzləşdirilmiş və paylanmış arxitekturalar, SNMP menecer–agent modeli, Syslog hadisələri, performans ölçülməsi və sənədləşdirmə.

Bu veb kitab müəllifin 2024-cü il dərsliyinin 4-cü moduluna əsaslanan tədris əlavəsidir. İnteraktiv simulyasiyalar təlim üçün hazırlanıb; real Zabbix/Wireshark mühitinə qoşulmur.
BÖLMƏ 4.1

4.1. Şəbəkənin idarə edilməsinin əsas prinsipləri

Şəbəkənin idarə edilməsi avadanlıq, proqram təminatı, əlaqələr və xidmətlərin planlaşdırılması, konfiqurasiyası, müşahidəsi və nasazlıqlarının aradan qaldırılması prosesidir. Əsas məqsədlər əlçatanlıq, performans, təhlükəsizlik və davamlılıqdır.

Öyrənmə qeydi: FCAPS yanaşması: Fault (nasazlıq), Configuration (konfiqurasiya), Accounting (uçot), Performance (performans), Security (təhlükəsizlik).
FCAPSMonitorinqDiaqnostikaSənədləşmə

Sadə dillə: şəbəkə idarəetməsi nədir?

Təsəvvür edin ki, universitetin üç korpusu var. Hər korpusda kompüterlər, Wi-Fi giriş nöqtələri, printerlər, serverlər və kommutatorlar işləyir. Şəbəkə idarəetməsi bu qurğuların sadəcə qoşulu olmasına baxmaq deyil. Məqsəd onların normal işlədiyini bilmək, problem yarananda səbəbini tapmaq, konfiqurasiyanı qaydada saxlamaq və xidmətin dayanmasının qarşısını almaqdır.

Şəbəkə idarəçisini hava limanının dispetçerinə bənzətmək olar: dispetçer bütün təyyarələri izləyir, təhlükəli vəziyyəti görür və istiqamətləndirir. Şəbəkə administratoru da cihazları, trafik axınını və xidmətləri izləyir.

Şəbəkə idarəetməsinin gündəlik dövrü

Əsas idarəetmə funksiyaları

1. Konfiqurasiyanın idarə edilməsi

Router, switch, VLAN, IP, DNS, DHCP və digər parametrlərin düzgün qurulması, dəyişikliklərin qeydiyyatı və ehtiyat nüsxəsinin saxlanmasıdır.

Nümunə: yeni laboratoriya açılır. Ona ayrıca VLAN və IP diapazonu ayrılır.

2. Nasazlıqların idarə edilməsi

Problem baş verəndə onu aşkarlamaq, yerini müəyyənləşdirmək, təsirini qiymətləndirmək və aradan qaldırmaqdır.

Nümunə: 2-ci korpusun 2-ci mərtəbəsində internet yoxdur. Əvvəlcə switch portu, kabel və uplink yoxlanılır.

3. Performansın idarə edilməsi

Şəbəkənin sürətini, gecikməni, paket itkisini və cihazların yükünü izləməkdir.

Nümunə: videokonfrans zamanı səs kəsilir. Gecikmə və jitter ölçülür.

4. Təhlükəsizliyin idarə edilməsi

İcazəsiz girişin qarşısını almaq, istifadəçi səlahiyyətlərini və təhlükəsizlik hadisələrini izləməkdir.

Nümunə: naməlum cihaz şəbəkəyə qoşulub. Port və autentifikasiya jurnalı araşdırılır.

5. İstifadəçi və resurs uçotu

Kimlərin hansı resurslardan istifadə etdiyini və resursların necə yükləndiyini izləməkdir.

6. Hesabatlılıq

Hadisələrin, dəyişikliklərin, ölçmələrin və görülən tədbirlərin tarixçəsini saxlamaqdır.

Nasazlıqla işləməyin 3 əsas mərhələsi

  1. Aşkarlama və təsnifat: nasazlıq nədir, haradadır, neçə istifadəçiyə təsir edir?
  2. Təcridetmə: problemli hissəni müəyyənləşdirin. Məsələn, yalnız bir mərtəbə təsirlənirsə, bütün universitet şəbəkəsini deyil, həmin mərtəbənin uplink və switch hissəsini araşdırın.
  3. Bildiriş və aradan qaldırma: administratora xəbər verin, səbəbi düzəldin, sonra xidmətin bərpa olunduğunu yoxlayın.
Özünüzü yoxlayın

İstifadəçilər internetə çıxır, lakin video zənglərdə səs gecikir. İlk növbədə hansı idarəetmə istiqaməti araşdırılmalıdır?

BÖLMƏ 4.2

4.2. Şəbəkənin idarə edilməsi parametrləri

İdarəetmədə CPU və RAM yüklənməsi, interfeys statusu, trafik sürəti, gecikmə, paket itkisi, jitter və xidmət əlçatanlığı ölçülür. Göstəricilər zaman üzrə izlənərək normal səviyyə ilə müqayisə edilir.

Öyrənmə qeydi: Monitorinq hədləri təşkilatın real trafik profilinə görə müəyyənləşdirilməlidir; laboratoriyada verilən hədlər yalnız təlim üçündür.
CPU / RAMLatency / LossThroughput / QoS

Parametr nədir və niyə ölçürük?

Parametr şəbəkənin vəziyyətini rəqəmlə ifadə edən göstərici və ya işləmə qaydasıdır. Həkim temperatur, nəbz və təzyiqə baxaraq insanın vəziyyətini qiymətləndirdiyi kimi, administrator da CPU, RAM, trafik, gecikmə və paket itkisinə baxaraq şəbəkənin vəziyyətini qiymətləndirir.

CPU – prosessor yükü

Cihazın prosessoru nə qədər məşğuldur? Uzun müddət çox yüksək CPU marşrutlaşdırma, firewall və ya monitorinq proseslərinin gecikməsinə səbəb ola bilər.

RAM – operativ yaddaş

Cihazın yaddaşından nə qədər istifadə olunur? Yaddaş tükənərsə proseslər dayana, cihaz ləngiyə və ya yenidən başlaya bilər.

Bandwidth / Throughput

Bandwidth kanalın nəzəri tutumudur; throughput isə faktiki ötürülən məlumat sürətidir. 1 Gbit/s portda faktiki 300 Mbit/s ötürülməsi mümkündür.

Latency – gecikmə

Paketin mənbədən təyinat nöqtəsinə çatmasına sərf olunan vaxtdır. Adətən millisan (ms) ilə ölçülür.

Packet loss – paket itkisi

Göndərilən paketlərin neçə faizinin təyinat nöqtəsinə çatmadığını göstərir. Səs və video xidmətlərində hiss olunan problemlər yarada bilər.

Jitter – gecikmənin dəyişkənliyi

Paketlərin çatma vaxtları arasındakı fərqin dəyişməsidir. Orta gecikmə az olsa belə, jitter yüksəkdirsə səs qeyri-sabit eşidilə bilər.

Əsas ölçmə anlayışları

Əlçatanlıq (availability) xidmətin işlək olduğu vaxtın ümumi müşahidə vaxtına nisbətidir.

Əlçatanlıq (%) = işlək vaxt / ümumi vaxt × 100

Məsələn, xidmət 30 gün ərzində 29 gün 21 saat işləyibsə, dayanma 3 saatdır. Əlçatanlıq təxminən 99,58%-dir.

İstifadə faizi resursun tutumunun hansı hissəsinin istifadə olunduğunu göstərir. Hədd (threshold) administratorun xəbərdarlıq üçün təyin etdiyi sərhəddir. Həddin aşılması avtomatik olaraq nasazlıq demək deyil; araşdırma siqnalıdır.

BÖLMƏ 4.3

4.3. Müxtəlif şəbəkə idarəetmə arxitekturaları

Mərkəzləşdirilmiş arxitekturada monitorinq və idarəetmə əsas mərkəzdə toplanır. Paylanmış arxitekturada müxtəlif korpuslarda proxy və ya yerli toplayıcılar işləyə bilər. Hibrid yanaşma hər iki modelin üstünlüklərini birləşdirir.

Öyrənmə qeydi: Üç korpuslu universitetdə mərkəzi server və korpuslar üzrə toplayıcılar dayanıqlığı artırmaq üçün müzakirə edilə bilər.
MərkəzləşdirilmişPaylanmışHibrid

Arxitektura – idarəetmə işinin necə təşkil edilməsidir

Universitetin 3 korpusunda 50-dən çox şəbəkə cihazı olduğunu düşünün. Hər cihazın yanına administrator göndərmək səmərəli deyil. İdarəetmə arxitekturası monitorinq məlumatlarının harada toplanacağını və qərarların necə veriləcəyini müəyyən edir.

Mərkəzləşdirilmiş

Bütün cihazlar bir mərkəzi idarəetmə serverinə məlumat göndərir. İdarəetmə və hesabat vahiddir. Lakin mərkəzi server və ona gedən əlaqə kritik nöqtəyə çevrilə bilər.

Nümunə: bütün korpuslar bir NMS/Zabbix serverinə qoşulur.

Paylanmış / mərkəzləşdirilməmiş

Məlumat toplama və idarəetmə bir neçə qovşaq arasında bölünür. Bir sahədə əlaqə kəsilsə belə, yerli toplayıcı məlumatı saxlaya bilər. İdarəetmə və sazlama daha mürəkkəbdir.

Nümunə: hər korpusda lokal monitorinq toplayıcısı.

İyerarxik

Yerli səviyyələr öz sahələrini izləyir, yuxarı səviyyə ümumi mənzərəni görür. Yerli sistemlər məlumatı süzgəcdən keçirib mərkəzə ötürə bilər.

Nümunə: korpus üzrə proxy-lər, mərkəzdə ümumi panel.

SDN – proqramla idarə olunan şəbəkə

İdarəetmə məntiqi (control plane) paketlərin ötürülməsi funksiyasından (data plane) ayrılır. Nəzarətçi siyasətləri proqram vasitəsilə tətbiq edə bilər.

Nümunə: SDN controller şəbəkə axınlarının qaydalarını mərkəzləşdirilmiş şəkildə proqramlaşdırır.

BÖLMƏ 4.4

4.4. Şəbəkə idarəetmə sisteminin əsas komponentləri

İdarəetmə stansiyası (manager), cihazdakı agent, MIB/OID məlumat modeli, verilənlər bazası, vizuallaşdırma paneli, xəbərdarlıq mexanizmi və hadisə jurnalı əsas komponentlərdir.

Öyrənmə qeydi: Agent ölçüləri təqdim edir, monitorinq sistemi məlumatları saxlayır, trigger şərtləri pozulduqda bildiriş yaradır.
ManagerAgentMIB / OIDTrigger

İdarəetmə sisteminin 3 əsas hissəsi

Şəbəkə monitorinq sistemini poçt xidməti kimi düşünün: bir mərkəz məlumatı qəbul edir, sahədəki nümayəndələr məlumatı toplayır, hamısı ortaq qaydada danışır.

Menecer – agent – idarəetmə məlumat bazası (MIB)
1. NMS / Manager

Administratorun istifadə etdiyi idarəetmə stansiyasıdır. Cihazlardan sorğu ilə məlumat alır, göstəriciləri saxlayır, qrafik və xəbərdarlıq yaradır.

2. Agent

İdarə olunan cihazda işləyən proqram moduludur. Cihazın vəziyyətini oxuyur və menecerin sorğularına cavab verir.

3. MIB

İdarəetmə məlumat bazasıdır. Cihaz haqqında standartlaşdırılmış obyektləri və onların dəyərlərini təsvir edir.

4. İdarəetmə protokolu

Manager və agentin hansı formatda və necə danışacağını müəyyən edir. Bu modulda əsas nümunə SNMP-dir.

Bir sorğu necə işləyir?

1. Administrator CPU soruşur→2. NMS GET göndərir→3. Agent MIB-dən oxuyur→4. Cavab qayıdır→5. Panel yenilənir

Əgər agent özü problem aşkarlayarsa, menecerin sorğusunu gözləmədən bildiriş göndərə bilər. SNMP-də buna TRAP deyilir. Beləliklə, iki informasiya axını var: polling – menecerin vaxtaşırı soruşması; notification – agentin hadisə barədə özü xəbər verməsi.

Yadda saxla: NMS – idarəetmə mərkəzi; Agent – cihazdakı nümayəndə; MIB – cihaz məlumatlarının strukturu; OID – konkret obyektin unikal identifikatoru.
Mini-sual

Switch portu qəfil sönür. Administrator heç bir sorğu göndərmədən bildiriş alır. Bu hansı mexanizmdir?

BÖLMƏ 4.5

4.5. SNMP – Sadə şəbəkə idarəetmə protokolu

SNMP şəbəkə cihazlarının vəziyyəti və sayğacları haqqında məlumat əldə etməyə imkan verir. GET/GET-NEXT/GET-BULK sorğularla məlumat oxunur; SET yalnız icazəli və dəstəklənən obyektləri dəyişir; TRAP və INFORM bildiriş göndərir. Agent adətən UDP 161, bildirişlər isə UDP 162 istifadə edir.

Öyrənmə qeydi: SNMPv1 və SNMPv2c community sətrinə əsaslanır; SNMPv3 autentifikasiya və məxfilik mexanizmləri ilə daha uyğun seçimdir.
UDP 161UDP 162SNMPv3

SNMP nə üçündür?

SNMP (Simple Network Management Protocol) – şəbəkə cihazlarının vəziyyətini izləmək və idarəetmə məlumatlarını toplamaq üçün istifadə olunan protokoldur. Administrator hər switch-ə ayrıca daxil olmaq əvəzinə, NMS vasitəsilə cihazlardan standart formatda məlumat ala bilər.

SNMP cihazın CPU yükü, interfeys statusu, ötürülən baytların sayı, uptime və digər idarəetmə obyektləri haqqında məlumat verə bilər. SNMP özü bütün monitorinq sisteminin adı deyil; o, monitorinq platformasının cihazla danışmaq üçün istifadə etdiyi protokollardan biridir.

Əsas anlayışlar

OID

Object Identifier – MIB-də obyektin ünvanıdır. Məsələn, cihazın sistem adı üçün standart OID: 1.3.6.1.2.1.1.5.0.

MIB

Management Information Base – cihazın idarəetmə obyektlərinin iyerarxik təsviridir. MIB ağacında obyektlər OID ilə tapılır.

Manager

SNMP sorğularını göndərən və cavabları toplayan sistemdir.

Agent

Cihazda işləyən modul; MIB dəyərlərini təqdim edir və hadisə bildirişləri göndərə bilər.

SNMP versiyaları

SNMPv1

Əsas ilkin versiya. Community-string əsasında işləyir; müasir təhlükəsizlik tələbləri üçün məhdudiyyətləri var.

SNMPv2c

Performans və GET-BULK kimi imkanlar təkmilləşdirilib, lakin community-string qorunması şifrələmə təmin etmir.

SNMPv3

İstifadəçi əsaslı təhlükəsizlik modeli təqdim edir. Düzgün konfiqurasiya ilə autentifikasiya və məxfilik (şifrələmə) təmin oluna bilər.

Təhlükəsizlik qaydası: real şəbəkədə SNMPv3-ə üstünlük verin, community-string-ləri açıq saxlamayın, sorğuları idarəetmə VLAN-ı və etibarlı NMS ünvanları ilə məhdudlaşdırın. SET əməliyyatını yalnız zəruri olduqda və ciddi səlahiyyət nəzarəti ilə aktiv edin.

Portlar

Ənənəvi SNMP sorğuları adətən UDP 161, agent bildirişləri (TRAP/INFORM) isə UDP 162 portundan istifadə edir.

SNMP əməliyyatını sınayın

BÖLMƏ 4.6

4.6. Sistem və şəbəkə proqramları

Zabbix hostları, göstəriciləri, triggerləri və qrafikləri izləmək üçün; Wireshark paketlərin təhlili üçün; Syslog hadisə qeydlərini mərkəzləşdirmək üçün istifadə olunur. Ping və traceroute diaqnostikaya kömək edir.

Öyrənmə qeydi: Wireshark-da SNMP paketləri üçün 'snmp', Syslog üçün 'syslog' filtri istifadə oluna bilər; konkret protokolun dekodlaşdırılması paket formatından asılıdır.
ZabbixWiresharkSyslog

Hansı proqram hansı işi görür?

Şəbəkənin idarə edilməsi bir proqramla bitmir. Müxtəlif proqramlar fərqli işi yerinə yetirir: biri cihazları izləyir, digəri paketləri təhlil edir, başqa biri hadisə jurnallarını toplayır.

Zabbix – monitorinq platforması

Server, switch, router və xidmətlərdən göstəricilər toplayır; qrafik, trigger, xəbərdarlıq və hesabat yaradır. SNMP, agent və digər üsullarla məlumat ala bilər.

Nümunə: CPU 90%-dən yuxarı 5 dəqiqə qalarsa xəbərdarlıq yaratmaq.

Wireshark – paket analizatoru

Şəbəkə interfeysindən tutulan paketləri göstərir. Mənbə/təyinat IP-si, protokol, port və paket ardıcıllığını təhlil etməyə kömək edir.

Nümunə: DNS sorğusu cavabsız qalırmı, TCP retransmission varmı?

Syslog – hadisə jurnalı

Router, switch, server və digər sistemlərin hadisə mesajlarını mərkəzi log serverinə ötürmək üçün istifadə olunur.

Nümunə: “interface down”, istifadəçi login-i, konfiqurasiya dəyişikliyi.

Ping və traceroute

Ping IP səviyyəsində əlçatanlığı və cavab vaxtını yoxlayır. Traceroute paketlərin keçdiyi marşrutdakı hop-ları göstərir.

Nümunə: serverə yolun hansı mərhələsində gecikmə artdığını araşdırmaq.

SSH / konfiqurasiya alətləri

Cihazlara təhlükəsiz uzaqdan daxil olmaq, konfiqurasiya oxumaq və dəyişiklikləri idarə etmək üçün istifadə edilir.

SNMP utilitləri

OID-ləri sorğulamaq, agent cavablarını yoxlamaq və MIB məlumatlarını araşdırmaq üçün istifadə olunur.

Syslog mesajı necə oxunur?

Syslog hadisə mesajı adətən göndərən cihaz, vaxt, proqram/proses, prioritet/severity və hadisə mətnini ehtiva edir. Severity səviyyəsi hadisənin ciddiliyini anlamağa kömək edir.

SeverityAdıİzah
0EmergencySistem işləyə bilmir
1AlertDərhal tədbir tələb edir
2CriticalKritik vəziyyət
3ErrorXəta baş verib
4WarningXəbərdarlıq
5NoticeNormal, lakin diqqətəlayiq hadisə
6InformationalMəlumat xarakterli mesaj
7DebugDiaqnostika məlumatı

Syslog üçün UDP 514 geniş istifadə olunan ənənəvi portdur; mühitdən asılı olaraq TCP və TLS ilə qorunan ötürmə də tətbiq oluna bilər. Log serverə gələn məlumatın etibarlılığı üçün vaxt sinxronizasiyası, girişə nəzarət, saxlanma müddəti və ehtiyat nüsxəsi vacibdir.

Wireshark-da nə axtarırıq?

Wireshark paketləri tutub göstərir. Display filter nümunələri:

  • icmp – ICMP paketləri;
  • dns – DNS sorğu və cavabları;
  • tcp.port == 443 – TCP 443 portu;
  • snmp – SNMP trafiki;
  • ip.addr == 10.10.1.10 – konkret IP ilə əlaqəli paketlər.
Fərqi yadda saxla: Zabbix “şəbəkə necə işləyir?” sualına göstəricilər və xəbərdarlıqlarla cavab verir; Wireshark “paket səviyyəsində nə baş verdi?” sualını araşdırır; Syslog “cihaz hansı hadisəni qeydə aldı?” sualına cavab verir.
Aləti seç

“TCP bağlantısında retransmission baş verir, paketləri bir-bir araşdırmaq istəyirəm.” Hansı alət?

BÖLMƏ 4.7

4.7. Şəbəkə sənədləri

Şəbəkə topologiyası, IP/VLAN planı, cihaz inventarı, interfeys xəritəsi, ehtiyat nüsxə və dəyişiklik jurnalı, insident hesabatları və əlaqə siyahısı idarəetmənin vacib hissəsidir.

Öyrənmə qeydi: Sənədlər tarix, məsul şəxs və dəyişiklik səbəbi ilə saxlanmalıdır.
TopologiyaİnventarDəyişiklik jurnalı

Şəbəkə sənədi – şəbəkənin xəritəsi və yaddaşı

Administrator işdən ayrılsa və ya gecə saatlarında qəza baş versə, başqa mütəxəssis şəbəkənin necə qurulduğunu bilməlidir. Sənədləşmə məhz bu bilikləri şəxsin yaddaşından çıxarıb təşkilatın istifadəsinə verir.

1. Fiziki və məntiqi diaqram

Hansı cihaz haradadır, hansı porta və kabelə qoşulub? VLAN-lar, IP şəbəkələri və marşrutlar necə qurulub?

2. Cihaz inventarı

Cihazın adı, modeli, seriya nömrəsi, IP ünvanı, yeri, proqram versiyası, zəmanət və məsul şəxs.

3. Konfiqurasiya sənədi

VLAN, IP, routing, DHCP, DNS, ACL, SNMP, Syslog və ehtiyat nüsxə qaydaları.

4. Əməliyyat proseduru

Nasazlıq zamanı kimə müraciət edilir, hansı ardıcıllıqla yoxlama aparılır, dəyişiklik necə təsdiqlənir?

5. Monitorinq və performans hesabatı

CPU, RAM, trafik, gecikmə, paket itkisi, əlçatanlıq və hadisələrin dövri xülasəsi.

6. Dəyişiklik jurnalı

Kim, nə vaxt, hansı səbəblə nəyi dəyişib; nəticə nə olub; geri qaytarma planı varmı?

Sənədin keyfiyyət yoxlama siyahısı

  • Şəbəkə diaqramında cihaz adları və əlaqələr oxunaqlıdır.
  • IP/VLAN cədvəli faktiki konfiqurasiya ilə uyğundur.
  • Tarix, versiya, sənəd sahibi və təsdiq edən şəxs göstərilib.
  • Dəyişiklikdən sonra sənəd yenilənib.
  • Parollar və gizli açarlar sənəddə açıq mətnlə saxlanmır; təhlükəsiz sirr meneceri istifadə olunur.
  • Ehtiyat nüsxələr qorunan yerdə saxlanılır və bərpa sınağı edilir.
Sənədləşmə sınağı

Switch-in konfiqurasiyası dəyişdirilib, amma diaqram və VLAN cədvəli yenilənməyib. Bu hansı risk yaradır?

BÖLMƏ 4.8

4.8. Yoxlama sualları

Bu bölmədə dərsliyin yoxlama mövzuları üzrə situasiya əsaslı özünüqiymətləndirmə və avtomatik nəticə hesablanması təqdim edilir.

Öyrənmə qeydi: 10 sual və 7 müxtəlif tapşırıq formatı.

Yoxlama suallarına hazırlaşmaq üçün mövzu xəritəsi

Bu bölmədə dərslikdəki yoxlama istiqamətləri üzrə özünüzü qiymətləndirin. Cavab verərkən tərifi yazmaqla kifayətlənməyin; universitet şəbəkəsindən nümunə göstərin.

  1. Şəbəkə idarəetməsinin məqsədi və əsas funksiyaları hansılardır?
  2. Nasazlığın aşkarlanması, təcrid edilməsi və aradan qaldırılması necə aparılır?
  3. CPU, RAM, gecikmə, paket itkisi və jitter nəyi göstərir?
  4. IP, DNS, DHCP, NAT, VLAN, QoS, Firewall və VPN idarəetmədə hansı rolu oynayır?
  5. Mərkəzləşdirilmiş, paylanmış, iyerarxik və SDN arxitekturaları necə fərqlənir?
  6. NMS, agent, MIB və SNMP arasında əlaqə nədir?
  7. GET, GET-NEXT, GET-BULK, SET, TRAP və INFORM nə üçün istifadə olunur?
  8. SNMPv1, SNMPv2c və SNMPv3 arasında təhlükəsizlik fərqi nədir?
  9. Syslog və Wireshark şəbəkə probleminin araşdırılmasında nə ilə fərqlənir?
  10. Şəbəkə diaqramı, inventar, konfiqurasiya və dəyişiklik jurnalı niyə lazımdır?
  11. QoS nədir və səs/video trafikinə necə üstünlük verir?
Cavab strategiyası: anlayışı təriflə → necə işlədiyini izah et → real nümunə göstər → üstünlük və məhdudiyyəti qeyd et.
BÖLMƏ 4.9

4.9. Praktiki tapşırıq

Laboratoriya işi № 4. SNMP və Syslog vasitəsilə şəbəkənin monitorinqi və idarə edilməsi. Üç korpusun hər birində üç mərtəbə olan universitet şəbəkəsində cihazları izləyin, nasazlıq yaradın, SNMP və Syslog nəticələrini əlaqələndirin və hesabat hazırlayın.

Öyrənmə qeydi: Bütün ssenarilər lokal, təlim xarakterli modellərdir; real qurğulara sorğu göndərilmir.

Praktiki tapşırığı necə yerinə yetirməli?

Dərslikdəki praktiki istiqamətlər əsasında tələbə avadanlığı tanımalı, diaqnostika aparmalı, Syslog və trafik təhlili etməli, sonda şəbəkə sənədlərini hazırlamalıdır.

Avadanlığı tanı→Əlçatanlığı yoxla→Jurnalı təhlil et→Paketə bax→Sənədləşdir

Nümunə iş ssenarisi

2-ci korpusun 1-ci mərtəbəsində istifadəçilər daxili serverə qoşula bilmir. Monitorinq panelində switch portunun statusu “down” göstərilir, Syslog-da “interface link down” qeydi var.

  1. Hadisənin vaxtını və təsir dairəsini qeyd edin.
  2. Switch portunun statusunu və fiziki kabeli yoxlayın.
  3. Ping ilə gateway və server əlçatanlığını test edin.
  4. Wireshark ilə uyğun test trafikini izləyin; paketlərin hara qədər getdiyini araşdırın.
  5. Nasazlıq aradan qaldırıldıqdan sonra yenidən ölçmə aparın.
  6. Görülən işi dəyişiklik jurnalına yazın və diaqramı yeniləyin.
Əsas qayda: diaqnostikada bir dəfəyə çox dəyişiklik etməyin. Əvvəl müşahidə və ölçmə, sonra bir dəyişiklik, sonda yenidən test.

4.9 · PRAKTİKİ TAPŞIRIQ

Laboratoriya işi № 4. SNMP və Syslog vasitəsilə şəbəkənin monitorinqi və idarə edilməsi

İşin məqsədi

Şəbəkə monitorinq sistemini qurmaq, SNMP və Syslog məlumatlarını təhlil etmək, CPU/RAM/trafik/bağlantı göstəricilərini izləmək, gecikmə və paket itkisini qiymətləndirmək, nəticələri qrafik və hesabatla təqdim etmək.

Nəzəri hissə

SNMP agentlərdən göstəricilərin oxunmasına və hadisə bildirişlərinin qəbuluna imkan verir. Syslog cihazların əməliyyat hadisələrini saxlayır və mərkəzi jurnala ötürə bilir. Zabbix göstəriciləri toplayaraq triggerlər və qrafiklər yaradır. Wireshark paket səviyyəsində diaqnostikaya kömək edir.

Praktiki hissə — işin ardıcıllığı

  1. Üç korpus və doqquz mərtəbəli şəbəkənin topologiyasını araşdırın; iki fərqli qurğu seçin.
  2. Normal rejimdə CPU, RAM, trafik, gecikmə və paket itkisini qeydə alın.
  3. SNMP GET və GET-BULK sorğularını işlədin; OID cavablarını müqayisə edin.
  4. SNMPv2c və SNMPv3 təhlükəsizlik fərqini izah edin; TRAP və INFORM sınağını aparın.
  5. “Link down” və “CPU yüklənməsi” hadisələrini yaradın; Syslog qeydlərini müqayisə edin.
  6. Wireshark paket nümunələrində SNMP, Syslog və ICMP başlıqlarını müəyyən edin.
  7. QoS prioritetini dəyişdirərək sadələşdirilmiş modeldə gecikmə fərqini müşahidə edin.
  8. Topologiya, cihaz inventarı, insident səbəbi, bərpa addımı və qrafik müşahidələrini hesabatda sənədləşdirin.
